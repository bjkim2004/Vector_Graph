    HANDS-ON LAB · 8강 Cypher 기초

    Cypher 기초 실습: 넷플릭스 영화 추천 그래프 만들기

    "이 영화를 본 회원이 함께 본 영화"는 어떻게 찾을까요? 회원과 영화를 그래프로 직접 만들고, 찾고, 고치고, 지우고, 세어 본 다음, 마지막에 나만의 첫 추천 쿼리를 완성합니다.

    소요 시간 약 120~150분대응 강의 8. Cypher 기초 — 패턴 매칭과 CRUD준비물 비어 있는 AuraDB 인스턴스(Free 가능)표기 라벨·관계 타입·속성·변수는 한글, 예약어만 영문검증 모든 쿼리를 실제 AuraDB Free 인스턴스(Cypher 5, 런타임 2026.10.2)에서 실행해 확인 (2026-11-22). 행 순서와 DB Hits는 환경에 따라 조금 다를 수 있습니다데이터 영화 정보는 학습용으로 단순화했습니다(장르 1개, 러닝타임은 근사값). 회원은 가상 인물이며 실제 넷플릭스 제공 여부와는 무관합니다
    회원영화처음 그래프 노드 5 · 관계 4확장 후 노드 15 · 관계 21
    STEP 00

    그래프 데이터베이스 한눈에 보기

    목표 노드 · 관계 · 속성이 어떻게 생겼는지와 실습 진행 방법을 확인합니다.

    왜 추천에 그래프를 쓸까

    진행 방법 각 코드 블록의 복사 버튼을 누르고 → Aura의 Query 화면 편집기에 붙여 넣고 → 실행(▶ 또는 Ctrl+Enter)합니다. 그리고 바로 아래 예상 결과와 내 화면을 비교합니다.
    여러 블록을 한꺼번에 붙여 넣지 마세요 한 블록 안에 문장이 여러 개면 결과는 문장별 목록(상태 표시 + 쿼리)으로 나오고, 행을 펼치거나 View results를 눌러야 각 결과가 보입니다. 그리고 오류가 난 문장에서 실행이 멈춰 그 뒤 문장은 실행되지 않습니다.
    STEP 01

    시작 전 준비

    목표 실습용 데이터베이스가 비어 있는지 확인합니다.

    01-1 · 데이터 개수 확인
    MATCH (n) RETURN count(n) AS 노드수;
    실행 결과 · AuraDB
    0이 아니라면: 데이터베이스 비우기
    체크포인트 · 그대로 붙여 넣어 실행
    MATCH (n) DETACH DELETE n;
DROP CONSTRAINT 영화_제목_고유 IF EXISTS;
DROP CONSTRAINT 회원_이름_고유 IF EXISTS;

    다른 실습에서 만든 제약조건이 더 있다면 SHOW CONSTRAINTS;로 이름을 확인하고 DROP CONSTRAINT 이름;으로 지웁니다.

    주의 이 실습은 마지막 STEP에서 모든 노드를 지웁니다. 다른 데이터가 들어 있지 않은 실습 전용 인스턴스에서만 진행하세요.
    STEP 02

    패턴 읽는 법: 괄호는 노드, 화살표는 관계

    목표 Cypher 문장은 그래프를 글자로 그린 그림입니다.

    02-1 · 패턴의 구조 (실행하지 않고 읽기)
    // (변수:라벨 {속성})-[변수:타입 {속성}]->(변수:라벨 {속성})
//
// (회원:회원 {이름: '김지민'})-[:시청 {별점: 5}]->(영화:영화)
//   └ 노드 패턴                 └ 관계 패턴          └ 노드 패턴
//
// (n)         라벨·속성 생략 → 아무 노드나
// (:영화)     변수 생략 → 라벨만 지정
// -[:시청]-   화살촉 생략 → 방향을 가리지 않음
    02-2 · 데이터가 없어도 실행되는 RETURN
    RETURN '안녕, 그래프!' AS 인사, 1 + 2 AS 합, ['스릴러', 'SF'] AS 장르목록;
    실행 결과 · AuraDB
    STEP 03

    첫 그래프 만들기: CREATE

    목표 CREATE로 영화 3편과 회원 2명을 만들고, 시청·찜 관계로 연결합니다.

    ① 노드 하나 만들기

    03-1 · 영화 노드 1개 (한 번만 실행)
    CREATE (:영화 {제목: '기생충', 개봉연도: 2019, 장르: '스릴러', 러닝타임: 132});
    실행 결과 · AuraDB
    03-2 · 방금 만든 노드 확인
    MATCH (영화:영화) RETURN 영화;
    실행 결과 · AuraDB

    ② 나머지 노드 만들기

    03-3 · 영화 2편과 회원 2명 (문장 4개를 한 번에)
    CREATE (:영화 {제목: '부산행', 개봉연도: 2016, 장르: '액션', 러닝타임: 118});
CREATE (:영화 {제목: '승리호', 개봉연도: 2021, 장르: 'SF', 러닝타임: 136});
CREATE (:회원 {이름: '김지민', 나이: 24, 요금제: '프리미엄'});
CREATE (:회원 {이름: '이서준', 나이: 31, 요금제: '스탠다드'});
    실행 결과 · AuraDB

    ③ 관계로 연결하기

    03-4 · 김지민이 기생충을 시청 (별점 5)
    MATCH (회원:회원 {이름: '김지민'})
MATCH (영화:영화 {제목: '기생충'})
CREATE (회원)-[:시청 {별점: 5}]->(영화);
    실행 결과 · AuraDB
    03-5 · 나머지 관계 3개
    MATCH (회원:회원 {이름: '김지민'})
MATCH (영화:영화 {제목: '부산행'})
CREATE (회원)-[:시청 {별점: 4}]->(영화);

MATCH (회원:회원 {이름: '이서준'})
MATCH (영화:영화 {제목: '기생충'})
CREATE (회원)-[:시청 {별점: 4}]->(영화);

MATCH (회원:회원 {이름: '이서준'})
MATCH (영화:영화 {제목: '승리호'})
CREATE (회원)-[:찜]->(영화);

    ④ 제대로 만들어졌는지 확인

    03-6 · 노드 수와 관계 수
    MATCH (n) RETURN count(n) AS 노드수;
MATCH ()-[r]->() RETURN count(r) AS 관계수;
    실행 결과 · AuraDB
    03-7 · 전체 그래프 보기
    MATCH (a)-[r]->(b) RETURN a, r, b;
    실행 결과 · AuraDB
    숫자가 다르다면: 체크포인트 A로 복구 (노드 5 · 관계 4)
    체크포인트 · 그대로 붙여 넣어 실행
    MATCH (n) DETACH DELETE n;

CREATE (기생충:영화 {제목: '기생충', 개봉연도: 2019, 장르: '스릴러', 러닝타임: 132}),
       (부산행:영화 {제목: '부산행', 개봉연도: 2016, 장르: '액션', 러닝타임: 118}),
       (승리호:영화 {제목: '승리호', 개봉연도: 2021, 장르: 'SF', 러닝타임: 136}),
       (지민:회원 {이름: '김지민', 나이: 24, 요금제: '프리미엄'}),
       (서준:회원 {이름: '이서준', 나이: 31, 요금제: '스탠다드'}),
       (지민)-[:시청 {별점: 5}]->(기생충),
       (지민)-[:시청 {별점: 4}]->(부산행),
       (서준)-[:시청 {별점: 4}]->(기생충),
       (서준)-[:찜]->(승리호);

    전부 지우고 한 문장으로 다시 만듭니다.

    STEP 04

    노드 찾기: MATCH와 RETURN

    목표 라벨과 속성으로 노드를 찾고, 필요한 속성만 골라 표로 받습니다.

    04-1 · 모든 영화의 제목과 개봉연도
    MATCH (영화:영화)
RETURN 영화.제목, 영화.개봉연도;
    실행 결과 · AuraDB
    04-2 · AS로 열 이름 붙이기
    MATCH (영화:영화)
RETURN 영화.제목 AS 제목, 영화.개봉연도 AS 개봉연도;
    실행 결과 · AuraDB
    04-3 · 속성으로 한 편만 찾기
    MATCH (영화:영화 {제목: '기생충'})
RETURN 영화.제목 AS 제목, 영화.장르 AS 장르, 영화.러닝타임 AS 러닝타임;
    실행 결과 · AuraDB

    결과가 비었을 때

    04-4 · 값에 오타가 있으면 (일부러 틀린 예)

RETURN 영화.제목 AS 제목;
    실행 결과 · AuraDB
    04-5 · 속성 이름에 오타가 있으면 (일부러 틀린 예)
    MATCH (영화:영화)
RETURN 영화.제목 AS 제목, 영화.개봉년도 AS 개봉연도;
    실행 결과 · AuraDB
    직접 바꿔 보기

    04-3의 제목을 '승리호'로 바꿔 실행해 보세요. 그다음 MATCH (회원:회원) RETURN 회원.이름 AS 이름, 회원.요금제 AS 요금제;를 직접 입력해 회원 2명을 조회해 보세요.

    STEP 05

    관계 따라가기: 화살표로 이웃 찾기

    목표 노드에서 관계를 따라 이웃 노드로 이동합니다.

    05-1 · 김지민이 시청한 영화
    MATCH (회원:회원 {이름: '김지민'})-[:시청]->(영화:영화)
RETURN 영화.제목 AS 제목;
    실행 결과 · AuraDB
    05-2 · 관계의 속성(별점)도 함께
    MATCH (회원:회원 {이름: '김지민'})-[시청:시청]->(영화:영화)
RETURN 영화.제목 AS 제목, 시청.별점 AS 별점;
    실행 결과 · AuraDB
    05-3 · 반대로: 기생충을 본 회원
    MATCH (영화:영화 {제목: '기생충'})<-[시청:시청]-(회원:회원)
RETURN 회원.이름 AS 회원, 시청.별점 AS 별점;
    실행 결과 · AuraDB
    05-4 · 방향을 잘못 쓰면 (일부러 틀린 예)
    MATCH (회원:회원 {이름: '김지민'})<-[:시청]-(영화:영화)
RETURN 영화.제목 AS 제목;
    실행 결과 · AuraDB
    05-5 · 관계 타입을 정하지 않고 모두 보기
    MATCH (회원:회원 {이름: '이서준'})-[관계]->(영화:영화)
RETURN type(관계) AS 관계, 영화.제목 AS 제목;
    실행 결과 · AuraDB

    두 번 건너가기: 추천의 씨앗

    05-6 · 김지민과 같은 영화를 본 다른 회원
    MATCH (나:회원 {이름: '김지민'})-[:시청]->(영화:영화)<-[:시청]-(다른회원:회원)
RETURN 영화.제목 AS 같이본영화, 다른회원.이름 AS 회원;
    실행 결과 · AuraDB
    직접 바꿔 보기

    05-6에서 '김지민'을 '이서준'으로 바꾸면 누가 나올까요? 예상한 뒤 실행해 보세요. (답: 기생충 · 김지민)

    STEP 06

    조건과 정렬: WHERE · ORDER BY · LIMIT · DISTINCT

    목표 찾은 결과를 조건으로 거르고, 정렬하고, 몇 건만 자르고, 중복을 없앱니다.

    06-1 · 비교 조건: 2019년 이후 개봉작
    MATCH (영화:영화)
WHERE 영화.개봉연도 >= 2019
RETURN 영화.제목 AS 제목, 영화.개봉연도 AS 개봉연도;
    실행 결과 · AuraDB
    06-2 · 조건 여러 개: AND · OR · IN
    MATCH (영화:영화)
WHERE 영화.러닝타임 >= 130 AND 영화.개봉연도 < 2020
RETURN 영화.제목 AS 제목;

MATCH (영화:영화)
WHERE 영화.장르 IN ['액션', 'SF']
RETURN 영화.제목 AS 제목, 영화.장르 AS 장르;
    실행 결과 · AuraDB
    06-3 · 관계 속성으로 거르기: 별점 5만
    MATCH (회원:회원)-[시청:시청]->(영화:영화)
WHERE 시청.별점 >= 5
RETURN 회원.이름 AS 회원, 영화.제목 AS 제목, 시청.별점 AS 별점;
    실행 결과 · AuraDB
    06-4 · 정렬하고 위에서 2건만
    MATCH (영화:영화)
RETURN 영화.제목 AS 제목, 영화.러닝타임 AS 러닝타임
ORDER BY 러닝타임 DESC
LIMIT 2;
    실행 결과 · AuraDB
    06-5 · 건너뛰기: SKIP (페이지 넘기기)
    MATCH (영화:영화)
RETURN 영화.제목 AS 제목, 영화.개봉연도 AS 개봉연도
ORDER BY 개봉연도
SKIP 1 LIMIT 1;
    실행 결과 · AuraDB
    06-6 · 중복 제거: DISTINCT
    MATCH (회원:회원)-[:시청]->(:영화)
RETURN 회원.이름 AS 시청한회원;

MATCH (회원:회원)-[:시청]->(:영화)
RETURN DISTINCT 회원.이름 AS 시청한회원;
    실행 결과 · AuraDB
    06-7 · 문자열 조건: CONTAINS · STARTS WITH · ENDS WITH
    MATCH (영화:영화)
WHERE 영화.제목 CONTAINS '행'
   OR 영화.제목 STARTS WITH '기'
RETURN 영화.제목 AS 제목;
    실행 결과 · AuraDB
    직접 바꿔 보기

    ① 러닝타임이 가장 짧은 영화 1편을 조회해 보세요. ② 30세 이상인 회원을 조회해 보세요. (답: 부산행 118 / 이서준)

    STEP 07

    없는 것 찾기: OPTIONAL MATCH와 WHERE NOT

    목표 "아직 아무도 안 본 영화", "찜만 하고 안 본 영화"처럼 관계가 없는 경우를 다룹니다.

    07-1 · 먼저 문제 확인: MATCH만 쓰면
    MATCH (영화:영화)<-[:시청]-(회원:회원)
RETURN 영화.제목 AS 제목, 회원.이름 AS 본사람
ORDER BY 제목;
    실행 결과 · AuraDB
    07-2 · OPTIONAL MATCH: 없으면 null로 채워서 남긴다
    MATCH (영화:영화)
OPTIONAL MATCH (영화)<-[:시청]-(회원:회원)
RETURN 영화.제목 AS 제목, 회원.이름 AS 본사람
ORDER BY 제목;
    실행 결과 · AuraDB
    07-3 · WHERE NOT 패턴: 아무도 안 본 영화
    MATCH (영화:영화)
WHERE NOT (영화)<-[:시청]-(:회원)
RETURN 영화.제목 AS 아무도안본영화;
    실행 결과 · AuraDB
    07-4 · 찜만 하고 아직 안 본 영화
    MATCH (회원:회원)-[:찜]->(영화:영화)
WHERE NOT (회원)-[:시청]->(영화)
RETURN 회원.이름 AS 회원, 영화.제목 AS 찜만한영화;
    실행 결과 · AuraDB
    직접 바꿔 보기

    07-2의 OPTIONAL MATCH를 MATCH로 바꿔 실행하면 몇 행이 나올까요? (답: 3행. 승리호가 다시 사라집니다)

    STEP 08

    안전하게 만들기: 제약조건과 MERGE

    목표 CREATE는 무조건 새로 만들고, MERGE는 있으면 찾고 없으면 만듭니다.

    ① CREATE와 MERGE의 차이를 횟수로 확인

    08-1 · CREATE는 실행할 때마다 생긴다 (두 번 실행하세요)
    CREATE (:연습 {내용: 'CREATE로 만듦'});
    08-2 · MERGE는 몇 번 실행해도 하나 (두 번 실행하세요)
    MERGE (:연습 {내용: 'MERGE로 만듦'});
    08-3 · 개수 확인
    MATCH (연습:연습)
RETURN 연습.내용 AS 내용, count(*) AS 개수;
    실행 결과 · AuraDB
    08-4 · 연습용 노드 지우기 (반드시 실행)
    MATCH (연습:연습) DELETE 연습;

    ② 고유 제약조건: 중복을 데이터베이스가 막게 하기

    08-5 · 영화 제목과 회원 이름은 겹칠 수 없다
    CREATE CONSTRAINT 영화_제목_고유 IF NOT EXISTS
FOR (영화:영화) REQUIRE 영화.제목 IS UNIQUE;

CREATE CONSTRAINT 회원_이름_고유 IF NOT EXISTS
FOR (회원:회원) REQUIRE 회원.이름 IS UNIQUE;
    실행 결과 · AuraDB
    여기서 오류가 난다면 이미 중복된 노드가 있다는 뜻입니다(예: STEP 03에서 CREATE를 두 번 실행). STEP 03의 체크포인트 A로 복구한 뒤 08-5를 다시 실행하세요.
    08-6 · 이제 CREATE로 중복을 만들면 (오류가 나는 것이 정상)
    CREATE (:영화 {제목: '기생충'});
    실행 결과 · AuraDB

    ③ MERGE로 새 회원 가입시키기

    08-7 · 있으면 찾고, 없으면 만든다 (두 번 실행하세요)
    MERGE (회원:회원 {이름: '박하윤'})
ON CREATE SET 회원.나이 = 27,
              회원.요금제 = '프리미엄',
              회원.가입일시 = datetime()

       회원.가입일시 IS NOT NULL AS 가입됨,

    MERGE (회원:회원 {이름: '박하윤'})

    STEP 13

    WITH: 중간 결과를 다음 단계로 넘기기

    목표 집계한 결과를 다시 거르거나, 그 결과에서 출발해 또 다른 패턴을 찾을 때 WITH를 씁니다.

    13-1 · 집계 결과에 WHERE를 바로 쓰면 (오류가 나는 것이 정상)
    MATCH (영화:영화)<-[:시청]-(:회원)
WHERE count(*) >= 3
RETURN 영화.제목;
    실행 결과 · AuraDB
    13-2 · WITH로 집계한 뒤 WHERE (SQL의 HAVING 역할)
    MATCH (영화:영화)<-[:시청]-(:회원)
WITH 영화, count(*) AS 시청수
WHERE 시청수 >= 3
RETURN 영화.제목 AS 제목, 시청수
ORDER BY 시청수 DESC;
    실행 결과 · AuraDB
    13-3 · 이어서 찾기: 인기작을 본 회원 목록
    MATCH (영화:영화)<-[:시청]-(:회원)
WITH 영화, count(*) AS 시청수
WHERE 시청수 >= 3
MATCH (영화)<-[:시청]-(회원:회원)
RETURN 영화.제목 AS 제목, 시청수, collect(회원.이름) AS 본회원
ORDER BY 시청수 DESC;

    13-5 · WITH … ORDER BY … LIMIT: 상위 몇 건만 남기고 이어 가기

WITH 영화, avg(시청.별점) AS 평균별점

    다듬기: 이웃이 좋게 본 영화만

    14-6 · 완성: 겹침 가중치 + 별점 4 이상 + TOP 3
    MATCH (나:회원 {이름: '김지민'})-[:시청]->(:영화)<-[:시청]-(이웃:회원)
WITH 나, 이웃, count(*) AS 겹침
MATCH (이웃)-[시청:시청]->(후보:영화)
WHERE NOT (나)-[:시청]->(후보)
  AND 시청.별점 >= 4
RETURN 후보.제목 AS 추천영화,
       sum(겹침) AS 점수,
       round(avg(시청.별점), 1) AS 이웃별점,
       collect(이웃.이름) AS 추천근거
ORDER BY 점수 DESC, 이웃별점 DESC, 추천영화
LIMIT 3;

    다른 방법: 내가 좋아한 장르에서 찾기

    14-7 · 콘텐츠 기반: 별점 4 이상 준 영화와 같은 장르인데 안 본 영화
    MATCH (나:회원 {이름: '김지민'})-[시청:시청]->(본영화:영화)
WHERE 시청.별점 >= 4

  AND NOT (나)-[:시청]->(후보)
RETURN 후보.장르 AS 장르, 후보.제목 AS 추천영화

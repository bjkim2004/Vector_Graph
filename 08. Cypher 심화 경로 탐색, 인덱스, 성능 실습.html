    STEP 02

    가변 길이 경로: *최소..최대

    목표 "친구의 친구의 친구"처럼 몇 다리를 건너 이어지는 노드를 한 번에 찾습니다.

    02-1 · 김지민에게서 친구 1~3단계 이내
    MATCH 경로 = (출발:회원 {이름: '김지민'})
      -[:친구*1..3]-(도착:회원)
RETURN 도착.이름 AS 회원,
       length(경로) AS 단계
ORDER BY 단계;
    실행 결과 · AuraDB
    02-2 · 회원별로 가장 가까운 단계만
    MATCH 경로 = (출발:회원 {이름: '김지민'})-[:친구*1..3]-(도착:회원)
RETURN 도착.이름 AS 회원, min(length(경로)) AS 단계
ORDER BY 단계, 회원;

    02-3 · 친구 추천: 친구의 친구 중 아직 친구가 아닌 회원

WHERE NOT (나)-[:친구]-(후보)
RETURN DISTINCT 후보.이름 AS 친구추천;

    STEP 03

    정확한 단계, 여러 관계 타입, 그리고 상한

    목표 영화를 사이에 두고 이어진 사람을 찾고, |로 관계 타입 여러 개를 동시에 지정하고, 상한 없는 탐색이 왜 위험한지 경로 수로 확인합니다.

    03-1 · 정확히 2단계: 송강호와 같은 영화에 출연한 배우
    MATCH (기준:배우 {이름: '송강호'})-[:출연*2]-(동료:배우)
RETURN 동료.이름 AS 함께출연한배우;
    실행 결과 · AuraDB
    03-2 · 관계 타입 여러 개: 송강호와 함께 작업한 사람 (배우 + 감독)
    MATCH (기준:배우 {이름: '송강호'})-[:출연|연출*2]-(동료)
RETURN DISTINCT 동료.이름 AS 함께작업한사람, labels(동료)[0] AS 역할
ORDER BY 역할, 함께작업한사람;

    03-3 · 한 방향으로만: 범죄도시의 후속편 따라가기 (상한 지정)

    STEP 04

    최단 경로: shortestPath · allShortestPaths

    목표 두 노드 사이를 가장 적은 관계로 잇는 경로를 찾습니다.

    04-1 · 송강호와 마동석 사이의 최단 경로 1개
    MATCH (시작:배우 {이름: '송강호'}),
      (도착:배우 {이름: '마동석'})
MATCH 경로 = shortestPath(
        (시작)-[:출연*..6]-(도착))
RETURN [노드 IN nodes(경로) |
        coalesce(노드.이름, 노드.제목)] AS 경로,
       length(경로) AS 거리;
    실행 결과 · AuraDB
    04-2 · 같은 거리의 모든 경로
    MATCH (시작:배우 {이름: '송강호'}),

MATCH 경로 = allShortestPaths(
        (시작)-[:출연*..6]-(도착))
RETURN [노드 IN nodes(경로) | coalesce(노드.이름, 노드.제목)] AS 경로;

    STEP 05

    경로 객체 분해와 reduce

    목표 경로는 노드와 관계가 번갈아 이어진 하나의 값입니다.

    05-1 · 경로를 세 함수로 분해
    MATCH (시작:감독 {이름: '장훈'}), (도착:배우 {이름: '송중기'})
MATCH 경로 = shortestPath((시작)-[:연출|출연*..6]-(도착))
RETURN [노드 IN nodes(경로) | coalesce(노드.이름, 노드.제목)] AS 노드목록,
       [관계 IN relationships(경로) | type(관계)] AS 관계목록,
       length(경로) AS 관계수;
    실행 결과 · AuraDB
    05-2 · reduce: 시리즈 정주행에 걸리는 시간
    MATCH 경로 = (:영화 {제목: '범죄도시'})-[:후속편*1..3]->(:영화)
RETURN [영화 IN nodes(경로) | 영화.제목] AS 정주행순서,
       reduce(합계 = 0,
              영화 IN nodes(경로)
              | 합계 + 영화.러닝타임) AS 총러닝타임
ORDER BY 총러닝타임;
    실행 결과 · AuraDB
    05-3 · 추천 이유를 경로로: 김지민에게 옥자를 추천하는 길
    MATCH 경로 = (:회원 {이름: '김지민'})-[:시청]->(:영화)<-[:시청]-(:회원)
             -[:시청]->(:영화 {제목: '옥자'})
RETURN [노드 IN nodes(경로) | coalesce(노드.이름, 노드.제목)] AS 추천경로,
       reduce(합 = 0, 관계 IN relationships(경로) | 합 + 관계.별점) AS 별점합
ORDER BY 별점합 DESC;

    STEP 06

    UNWIND와 CALL 서브쿼리

    목표 목록을 행으로 펼치는 UNWIND와, 바깥 행마다 따로 실행되는 CALL 서브쿼리로 "장르별 최신작 2편" 같은 그룹별 상위 N건을 구합니다.

    06-1 · UNWIND: 목록 원소 하나 = 행 하나
    WITH [3, 1, 2, 3, 1] AS 숫자들
UNWIND 숫자들 AS 숫자
RETURN collect(DISTINCT 숫자) AS 중복제거, sum(숫자) AS 합계, count(*) AS 개수;
    실행 결과 · AuraDB
    06-2 · 펼친 값으로 그래프 찾기
    UNWIND ['스릴러', 'SF'] AS 장르명
MATCH (:장르 {이름: 장르명})<-[:속함]-(영화:영화)
RETURN 장르명, collect(영화.제목) AS 영화들;
    실행 결과 · AuraDB
    06-3 · 장르별 최신작 2편씩
    MATCH (장르:장르)
CALL (장르) {
  MATCH (장르)<-[:속함]-(영화:영화)
  RETURN 영화
  ORDER BY 영화.개봉연도 DESC, 영화.제목
  LIMIT 2
}
RETURN 장르.이름 AS 장르,
       collect(영화.제목) AS 최신작
ORDER BY 장르;
    실행 결과 · AuraDB
    06-4 · 비교: 서브쿼리 없이 LIMIT을 쓰면
    MATCH (장르:장르)<-[:속함]-(영화:영화)
RETURN 장르.이름 AS 장르, 영화.제목 AS 제목, 영화.개봉연도 AS 개봉연도

    STEP 08

    추천 쿼리 심화: 유사도 · 콘텐츠 · 친구

    목표 07 실습의 추천 쿼리를 세 방향으로 키웁니다.

    ① 협업 필터링: 취향이 비슷한 이웃 찾기

    08-1 · 김지민과 다른 회원의 취향 유사도
    MATCH (나:회원 {이름: '김지민'})-[:시청]->(공통:영화)<-[:시청]-(이웃:회원)
WITH 나, 이웃, count(공통) AS 교집합
WITH 이웃, 교집합,
     COUNT { (나)-[:시청]->(:영화) }
     + COUNT { (이웃)-[:시청]->(:영화) }
     - 교집합 AS 합집합
RETURN 이웃.이름 AS 이웃, 교집합, 합집합,
       round(1.0 * 교집합 / 합집합, 2) AS 유사도
ORDER BY 유사도 DESC, 이웃;
    실행 결과 · AuraDB
    08-2 · 유사도를 가중치로 쓴 추천
    MATCH (나:회원 {이름: '김지민'})-[:시청]->(공통:영화)<-[:시청]-(이웃:회원)
WITH 나, 이웃, count(공통) AS 교집합
WITH 나, 이웃,
     1.0 * 교집합 / (COUNT { (나)-[:시청]->(:영화) }
                    + COUNT { (이웃)-[:시청]->(:영화) }
                    - 교집합) AS 유사도
MATCH (이웃)-[시청:시청]->(후보:영화)
WHERE NOT EXISTS { (나)-[:시청]->(후보) }
RETURN 후보.제목 AS 추천영화,
       round(sum(유사도 * 시청.별점), 2) AS 점수,
       collect(이웃.이름) AS 추천근거
ORDER BY 점수 DESC, 추천영화
LIMIT 5;
    실행 결과 · AuraDB

    ② 콘텐츠 기반: 장르 · 감독 · 배우가 겹치는 영화

    08-3 · 내가 별점 4 이상 준 영화와 공통점이 많은 영화
    MATCH (나:회원 {이름: '김지민'})-[시청:시청]->(본영화:영화)
WHERE 시청.별점 >= 4
MATCH (본영화)-[:속함|연출|출연]-(공통점)-[:속함|연출|출연]-(후보:영화)
WHERE NOT EXISTS { (나)-[:시청]->(후보) }
RETURN 후보.제목 AS 추천영화,
       count(*) AS 겹침점수,
       collect(DISTINCT 공통점.이름) AS 공통점
ORDER BY 겹침점수 DESC, 추천영화;
    실행 결과 · AuraDB

    ③ 친구 기반: 친구가 좋게 본 영화

    08-4 · 친구와 친구의 친구가 별점 4 이상 준 영화
    MATCH (나:회원 {이름: '김지민'})-[:친구*1..2]-(친구:회원)
WITH DISTINCT 나, 친구
MATCH (친구)-[시청:시청]->(후보:영화)
WHERE 시청.별점 >= 4
  AND NOT EXISTS { (나)-[:시청]->(후보) }
RETURN 후보.제목 AS 추천영화, count(*) AS 친구수, collect(친구.이름) AS 추천한친구
ORDER BY 친구수 DESC, 추천영화;

    ④ 모든 회원에게 한 편씩

    08-5 · 회원별 추천 1순위 (CALL 서브쿼리)
    MATCH (회원:회원)
CALL (회원) {
  MATCH (회원)-[:시청]->(:영화)<-[:시청]-(:회원)-[시청:시청]->(후보:영화)
  WHERE 시청.별점 >= 4
    AND NOT EXISTS { (회원)-[:시청]->(후보) }
  RETURN 후보.제목 AS 추천, count(*) AS 점수
  ORDER BY 점수 DESC, 추천
  LIMIT 1
}
RETURN 회원.이름 AS 회원, 추천, 점수
ORDER BY 회원;

    목표 인기순 정렬에 쓸 시청수를 영화 노드에 미리 계산해 저장합니다.

    12-1 · 영화마다 시청수 채우기: 3행마다 커밋
    :auto MATCH (영화:영화)
WHERE 영화.시청수 IS NULL
CALL (영화) {
  SET 영화.시청수 = COUNT { (영화)<-[:시청]-(:회원) }
} IN TRANSACTIONS OF 3 ROWS;
    실행 결과 · AuraDB
    :auto IN TRANSACTIONS는 질의가 스스로 트랜잭션을 여닫아야 해서, 화면이 미리 열어 둔 트랜잭션 안에서는 실행할 수 없습니다. 맨 앞의 :auto가 "자동 커밋으로 실행하라"는 화면 명령입니다.
    12-2 · 결과 확인: 저장해 둔 값으로 인기순
    MATCH (영화:영화)
RETURN 영화.제목 AS 제목, 영화.시청수 AS 시청수
ORDER BY 시청수 DESC, 제목
LIMIT 3;
    실행 결과 · AuraDB
    12-3 · 실행 중인 트랜잭션 보기
    SHOW TRANSACTIONS YIELD transactionId, currentQuery, elapsedTime
RETURN transactionId, currentQuery, elapsedTime;

    Q7(도전) STEP 08-3의 콘텐츠 기반 추천은 장르 · 감독 · 배우를 똑같이 1점으로 셉니다. 감독이 같으면 3점, 배우가 같으면 2점, 장르가 같으면 1점으로 가중치를 줘서 김지민의 추천 순위를 다시 구하세요. 힌트: sum(CASE WHEN 공통점:감독 THEN 3 … END)

    MATCH (나:회원 {이름: '김지민'})-[시청:시청]->(본영화:영화)

                ELSE 1 END) AS 점수

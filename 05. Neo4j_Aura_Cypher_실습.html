    HANDS-ON LAB · NEO4J AURA QUERY

    Neo4j Aura Cypher 실습

    Aura 콘솔의 Query 화면에서 사내 인재·기술 그래프를 직접 만들고, 조회·집계·추천·경로 탐색까지 단계별로 따라 하는 실습 자료입니다. 각 단계의 코드를 복사해 실행하고, 예상 결과와 비교하며 진행하세요.

    소요 시간 약 90~120분 대상 Cypher 처음 접하는 개발자·분석가 준비물 AuraDB 인스턴스(Free 가능) 접속 정보 검증 모든 쿼리를 실제 Aura 인스턴스에서 실행해 결과 확인(2026-11-07)
    Person 8 Team 3 Skill 7 Project 3 관계 51개
    STEP 00

    시작 전 준비: Query 화면에 연결하기

    목표 Aura 콘솔에서 인스턴스에 연결하고, 실습해도 되는 빈 데이터베이스인지 확인합니다.

    1. Aura 콘솔 Query 화면에 로그인합니다.
    2. 화면 상단(또는 연결 패널)에서 실습할 인스턴스를 선택합니다. 인스턴스가 Paused 상태라면 Instances 메뉴에서 먼저 Resume 합니다. Free 인스턴스는 한동안 쓰지 않으면 자동으로 일시정지됩니다.
    3. 접속 정보를 입력합니다. 사용자명은 보통 neo4j, 비밀번호는 인스턴스를 만들 때 내려받은 Neo4j-xxxx-Created-....txt 파일에 있습니다.
    4. 연결되면 에디터에 아래 쿼리를 붙여 넣고 실행합니다.
    00-1 · 데이터 개수 확인
    MATCH (n) RETURN count(n) AS nodeCount;
    예상 결과

    nodeCount = 0. 0이 아니면 다른 데이터가 들어 있는 인스턴스입니다.

    주의 STEP 13(정리)에서는 데이터베이스의 모든 노드를 지웁니다. 업무 데이터가 있는 인스턴스에서는 실습하지 말고, 실습 전용 인스턴스를 새로 만드세요.
    STEP 01

    Query 화면 둘러보기

    목표 쿼리를 입력·실행하고 결과를 그래프와 표로 바꿔 보는 방법을 익힙니다.

    쿼리 에디터Cypher를 입력하는 곳. Ctrl+Enter(Mac은 ⌘+Enter) 또는 실행(▶) 버튼으로 실행합니다.
    결과 카드실행할 때마다 카드가 하나씩 쌓입니다. 노드·관계를 반환하면 Graph, 값을 반환하면 Table로 보입니다. 카드 상단에서 보기 방식을 바꿀 수 있습니다.
    데이터베이스 정보왼쪽 사이드바에 라벨·관계 유형·속성 키 목록이 나옵니다. 항목을 누르면 해당 데이터를 조회하는 쿼리가 자동으로 실행됩니다.
    저장된 쿼리·기록자주 쓰는 쿼리는 저장해 두고, 이전에 실행한 쿼리는 기록에서 다시 불러올 수 있습니다.
    01-1 · 첫 실행
    RETURN '안녕하세요, Neo4j!' AS greeting, datetime() AS now;
    예상 결과

    Table 보기로 greeting과 현재 시각 now 한 행이 나옵니다.

    팁 세미콜론(;)으로 구분한 여러 문장을 한 번에 실행할 수 있습니다. 이때 결과 카드는 문장별 상태 목록(Results)으로 표시됩니다(STEP 04 화면 참고).
    STEP 02

    그래프 기초와 첫 노드

    목표 노드·관계·라벨·속성의 개념을 잡고, 노드 하나를 만들고 조회하고 지워 봅니다.

    • 노드(Node): 개체. 괄호로 씁니다. (p:Person {name:'김하늘'})
    • 라벨(Label): 노드의 종류. 콜론 뒤에 씁니다. :Person, :Skill
    • 관계(Relationship): 노드 사이의 연결. 방향과 유형이 있습니다. -[:HAS_SKILL]->
    • 속성(Property): 노드나 관계에 붙는 키-값. {level: 5}

    Cypher는 이 모양을 그대로 그리듯 씁니다. (사람)-[:보유]->(기술) 같은 ASCII 그림이 곧 쿼리입니다.

    02-1 · 노드 만들기
    CREATE (n:Test {name: '첫 노드', createdAt: datetime()})
RETURN n;
    예상 결과

    Graph 보기에 노드 1개가 나타납니다. 노드를 클릭하면 속성(name, createdAt)을 볼 수 있습니다.

    02-2 · 조회하기
    MATCH (n:Test)
RETURN n.name AS name, n.createdAt AS createdAt;
    02-3 · 지우기
    MATCH (n:Test)
DELETE n;
    예상 결과

    반환값 없이 "1개 노드 삭제" 같은 요약이 표시됩니다. 02-2를 다시 실행하면 결과가 비어 있습니다.

    STEP 04

    고유 제약조건 만들기

    목표 id가 중복되지 않도록 제약조건을 먼저 만듭니다. 제약조건을 만들면 해당 속성에 인덱스도 함께 생겨 조회가 빨라집니다.

    04-1 · 제약조건 4개
    CREATE CONSTRAINT person_id IF NOT EXISTS FOR (p:Person) REQUIRE p.id IS UNIQUE;
CREATE CONSTRAINT team_id IF NOT EXISTS FOR (t:Team) REQUIRE t.id IS UNIQUE;
CREATE CONSTRAINT project_id IF NOT EXISTS FOR (pj:Project) REQUIRE pj.id IS UNIQUE;
CREATE CONSTRAINT skill_name IF NOT EXISTS FOR (s:Skill) REQUIRE s.name IS UNIQUE;
    04-2 · 확인
    SHOW CONSTRAINTS YIELD name, labelsOrTypes, properties
RETURN name, labelsOrTypes, properties;
    예상 결과

    person_id, project_id, skill_name, team_id 4개 행.

    STEP 05

    실습 데이터 적재하기

    목표 UNWIND로 목록을 한 행씩 펼치고 MERGE로 노드·관계를 만듭니다. 05-1부터 순서대로 실행하세요.

    MERGE와 CREATE의 차이 CREATE는 실행할 때마다 새로 만들고, MERGE는 같은 것이 있으면 재사용하고 없을 때만 만듭니다. 그래서 아래 블록은 실수로 두 번 실행해도 데이터가 중복되지 않습니다.
    05-1 · 팀
    UNWIND [
  {id: 'T1', name: '데이터플랫폼팀'},
  {id: 'T2', name: 'AI서비스팀'},
  {id: 'T3', name: '보안팀'}
] AS row
MERGE (t:Team {id: row.id})
SET t.name = row.name
RETURN count(t) AS teams;
    05-2 · 직원 + 소속(WORKS_IN)
    UNWIND [
  {id: 'P01', name: '김하늘', title: '수석', years: 12, team: 'T1'},
  {id: 'P02', name: '이준호', title: '책임', years: 8,  team: 'T1'},
  {id: 'P03', name: '박서연', title: '선임', years: 4,  team: 'T1'},
  {id: 'P04', name: '최민재', title: '책임', years: 9,  team: 'T2'},
  {id: 'P05', name: '정유나', title: '선임', years: 5,  team: 'T2'},
  {id: 'P06', name: '한지우', title: '사원', years: 2,  team: 'T2'},
  {id: 'P07', name: '오세훈', title: '수석', years: 14, team: 'T3'},
  {id: 'P08', name: '윤가은', title: '선임', years: 6,  team: 'T3'}
] AS row
MATCH (t:Team {id: row.team})
MERGE (p:Person {id: row.id})
SET p.name = row.name, p.title = row.title, p.years = row.years
MERGE (p)-[:WORKS_IN]->(t)
RETURN count(p) AS persons;
    05-3 · 기술 + 보유(HAS_SKILL)
    UNWIND [
  ['P01', 'Spark', 5], ['P01', 'SQL', 5], ['P01', 'Python', 4], ['P01', 'Kubernetes', 3],
  ['P02', 'SQL', 4], ['P02', 'Python', 4], ['P02', 'Cypher', 3],
  ['P03', 'Python', 3], ['P03', 'Spark', 3],
  ['P04', 'Python', 5], ['P04', 'LLM', 5], ['P04', 'Kubernetes', 3],
  ['P05', 'Python', 4], ['P05', 'LLM', 4], ['P05', 'Cypher', 4],
  ['P06', 'Python', 2], ['P06', 'LLM', 2],
  ['P07', '보안진단', 5], ['P07', 'Kubernetes', 4],
  ['P08', '보안진단', 4], ['P08', 'Python', 3]
] AS row
MATCH (p:Person {id: row[0]})
MERGE (s:Skill {name: row[1]})
MERGE (p)-[h:HAS_SKILL]->(s)
SET h.level = row[2]
RETURN count(h) AS skills;
    05-4 · 프로젝트 + 필요 기술(REQUIRES)
    UNWIND [
  {id: 'PJ1', name: '고객360 지식그래프', year: 2026, requires: ['Cypher', 'Python', 'SQL']},
  {id: 'PJ2', name: '사내 RAG 챗봇',      year: 2026, requires: ['LLM', 'Python', 'Kubernetes']},
  {id: 'PJ3', name: '클라우드 보안점검',  year: 2025, requires: ['보안진단', 'Kubernetes']}
] AS row
MERGE (pj:Project {id: row.id})
SET pj.name = row.name, pj.year = row.year
WITH pj, row
UNWIND row.requires AS skillName
MATCH (s:Skill {name: skillName})
MERGE (pj)-[:REQUIRES]->(s)
RETURN count(*) AS requires;
    05-5 · 프로젝트 참여(WORKED_ON)
    UNWIND [
  ['P02', 'PJ1', 'PL'], ['P03', 'PJ1', '개발'], ['P05', 'PJ1', '개발'],
  ['P04', 'PJ2', 'PL'], ['P06', 'PJ2', '개발'], ['P01', 'PJ2', '데이터'],
  ['P07', 'PJ3', 'PL'], ['P08', 'PJ3', '진단']
] AS row
MATCH (p:Person {id: row[0]}), (pj:Project {id: row[1]})
MERGE (p)-[w:WORKED_ON]->(pj)
SET w.role = row[2]
RETURN count(w) AS workedOn;
    05-6 · 보고 체계(REPORTS_TO)
    UNWIND [['P02', 'P01'], ['P03', 'P01'], ['P04', 'P01'],
        ['P05', 'P04'], ['P06', 'P05'], ['P08', 'P07']] AS row
MATCH (a:Person {id: row[0]}), (b:Person {id: row[1]})
MERGE (a)-[:REPORTS_TO]->(b)
RETURN count(*) AS reportsTo;
    각 블록의 예상 결과

    05-1 teams 3 · 05-2 persons 8 · 05-3 skills 21 · 05-4 requires 8 · 05-5 workedOn 8 · 05-6 reportsTo 6

    05-5, 05-6에서 03N90: Cartesian product 알림이 보일 수 있습니다. 양쪽 노드를 고유 id로 하나씩만 찾기 때문에 이 경우는 무시해도 됩니다.

    STEP 06

    기본 조회: MATCH · WHERE · ORDER BY

    목표 조건으로 노드를 찾고, 원하는 속성만 골라 정렬합니다.

    06-1 · 연차 순 직원 목록
    MATCH (p:Person)
RETURN p.name AS name, p.title AS title, p.years AS years
ORDER BY years DESC;
    예상 결과

    8행. 첫 행 오세훈(14), 마지막 행 한지우(2).

    06-2 · 조건 걸기
    MATCH (p:Person)
WHERE p.years >= 8
RETURN p.name AS name, p.years AS years
ORDER BY years DESC;
    예상 결과

    오세훈 14 · 김하늘 12 · 최민재 9 · 이준호 8 (4행)

    06-3 · 목록 조건(IN)과 LIMIT
    MATCH (p:Person)
WHERE p.title IN ['수석', '책임']
RETURN p.name AS name, p.title AS title
ORDER BY p.years DESC
LIMIT 3;
    예상 결과

    오세훈 수석 · 김하늘 수석 · 최민재 책임. LIMIT을 지우면 이준호까지 4행이 나옵니다.

    팁 같은 조건을 속성 맵으로 줄여 쓸 수 있습니다. MATCH (p:Person {title: '수석'})는 WHERE p.title = '수석'과 같습니다.
    STEP 07

    관계 패턴 따라가기

    목표 화살표 패턴으로 연결된 데이터를 찾고, 관계에 붙은 속성으로 거릅니다. SQL의 JOIN을 패턴 하나로 대신합니다.

    07-1 · 특정 팀 구성원
    MATCH (p:Person)-[:WORKS_IN]->(t:Team {name: 'AI서비스팀'})
RETURN p.name AS name, p.title AS title;
    예상 결과

    최민재 · 정유나 · 한지우

    07-2 · 관계 속성으로 거르기
    MATCH (p:Person)-[h:HAS_SKILL]->(s:Skill {name: 'Python'})
WHERE h.level >= 4
RETURN p.name AS name, h.level AS level
ORDER BY level DESC, name;
    예상 결과

    최민재 5 · 김하늘 4 · 이준호 4 · 정유나 4

    07-3 · 방향 뒤집기
    MATCH (boss:Person {name: '김하늘'})<-[:REPORTS_TO]-(member:Person)
RETURN member.name AS directReport;
    예상 결과

    이준호 · 박서연 · 최민재. 화살표 방향이 "누가 누구에게 보고하는가"를 정합니다.

    07-4 · 한 사람 주변 그래프
    MATCH (p:Person {name: '정유나'})-[r]-(x)
RETURN p, r, x;
    예상 결과

    Graph 보기에 관계 7개: 소속 팀, 기술 3개(Python·LLM·Cypher), 프로젝트 1개, 상급자 최민재, 그리고 정유나에게 보고하는 한지우. 방향 없이 -[r]-로 쓰면 들어오고 나가는 관계를 모두 찾습니다.

    STEP 08

    집계: count · collect · avg

    목표 그룹별로 세고 모읍니다. Cypher에는 GROUP BY가 없고, RETURN에서 집계하지 않은 열이 자동으로 그룹 기준이 됩니다.

    08-1 · 팀별 인원과 구성원
    MATCH (t:Team)<-[:WORKS_IN]-(p:Person)
RETURN t.name AS team, count(p) AS headcount, collect(p.name) AS members
ORDER BY headcount DESC, team;
    예상 결과

    AI서비스팀 3 · 데이터플랫폼팀 3 · 보안팀 2 (members는 이름 목록)

    08-2 · 기술별 보유자 수
    MATCH (s:Skill)<-[:HAS_SKILL]-(p:Person)
RETURN s.name AS skill, count(p) AS holders
ORDER BY holders DESC, skill;
    예상 결과

    Python 7 · Kubernetes 3 · LLM 3 · Cypher 2 · SQL 2 · Spark 2 · 보안진단 2

    08-3 · 팀별 평균 연차
    MATCH (t:Team)<-[:WORKS_IN]-(p:Person)
RETURN t.name AS team, round(avg(p.years), 1) AS avgYears
ORDER BY avgYears DESC;
    예상 결과

    보안팀 10.0 · 데이터플랫폼팀 8.0 · AI서비스팀 5.3

    STEP 09

    여러 단계 건너기와 추천

    목표 두세 단계 떨어진 노드를 한 패턴으로 연결해, 동료 찾기와 인력 추천을 만들어 봅니다. 그래프 DB가 가장 빛나는 부분입니다.

    09-1 · 같은 프로젝트 동료
    MATCH (me:Person {name: '박서연'})-[:WORKED_ON]->(pj:Project)<-[:WORKED_ON]-(col:Person)
RETURN pj.name AS project, collect(col.name) AS colleagues;
    예상 결과

    고객360 지식그래프 · [이준호, 정유나]

    09-2 · 프로젝트에 맞는 인력 추천
    // PJ1에 필요한 기술을 가진 사람 중, 아직 PJ1에 참여하지 않은 사람
MATCH (pj:Project {id: 'PJ1'})-[:REQUIRES]->(s:Skill)<-[h:HAS_SKILL]-(p:Person)
WHERE NOT (p)-[:WORKED_ON]->(pj)
RETURN p.name AS candidate,
       collect(s.name) AS matchedSkills,
       count(s) AS matchCount,
       sum(h.level) AS levelSum
ORDER BY matchCount DESC, levelSum DESC;
    예상 결과

    김하늘 [SQL, Python] 2 · 9 → 최민재 1 · 5 → 윤가은 1 · 3 → 한지우 1 · 2. 목록 안의 순서는 실행 환경에 따라 다를 수 있습니다.

    09-3 · 없는 관계도 0으로 세기(OPTIONAL MATCH)
    MATCH (p:Person)
OPTIONAL MATCH (p)<-[:REPORTS_TO]-(m:Person)
RETURN p.name AS name, count(m) AS directReports
ORDER BY directReports DESC, name;
    예상 결과

    김하늘 3 · 오세훈 1 · 정유나 1 · 최민재 1 · 나머지 4명 0. OPTIONAL MATCH 대신 MATCH를 쓰면 부하 직원이 없는 4명이 결과에서 빠집니다. 직접 바꿔서 확인해 보세요.

    STEP 10

    경로 탐색: 가변 길이와 최단 경로

    목표 몇 단계인지 모르는 연결을 따라가고, 두 노드 사이의 최단 경로를 찾습니다.

    10-1 · 보고 체계 끝까지 따라가기
    MATCH path = (p:Person {name: '한지우'})-[:REPORTS_TO*1..]->(m:Person)
RETURN [n IN nodes(path) | n.name] AS chain, length(path) AS hops
ORDER BY hops;
    예상 결과

    [한지우, 정유나] 1 · [한지우, 정유나, 최민재] 2 · [한지우, 정유나, 최민재, 김하늘] 3

    10-2 · 두 사람 사이 최단 경로
    MATCH (a:Person {name: '한지우'}), (b:Person {name: '윤가은'})
MATCH path = shortestPath((a)-[*..6]-(b))
RETURN path;
    예상 결과

    길이 2 경로: 한지우 → Python ← 윤가은. 팀도 프로젝트도 다르지만 공통 기술로 바로 연결됩니다.

    10-3 · 관계 유형을 제한한 최단 경로
    MATCH (a:Person {name: '한지우'}), (b:Person {name: '윤가은'})
MATCH path = shortestPath((a)-[:REPORTS_TO|WORKS_IN|WORKED_ON*..8]-(b))
RETURN [n IN nodes(path) | coalesce(n.name, n.id)] AS route, length(path) AS hops;
    예상 결과

    결과가 비어 있습니다. 윤가은은 보안팀·클라우드 보안점검·오세훈과만 연결되어 있고, 이 셋은 소속·프로젝트·보고 관계로 다른 팀과 이어지지 않습니다. 기술(HAS_SKILL)을 빼면 두 사람 사이에 경로가 없다는 뜻입니다. 빈 결과도 의미 있는 답입니다.

    팁 *1..처럼 상한이 없는 가변 길이 패턴은 큰 그래프에서 매우 느려질 수 있습니다. 실무에서는 *1..5처럼 상한을 꼭 두세요.

    STEP 12

    데이터 수정과 삭제

    목표 속성을 바꾸고, MERGE의 ON CREATE / ON MATCH를 써 보고, 관계가 있는 노드를 안전하게 지웁니다. 이 단계부터는 데이터가 바뀌므로 앞 단계의 예상 결과와 달라질 수 있습니다.

    12-1 · 속성 수정(SET)
    MATCH (p:Person {name: '한지우'})
SET p.title = '선임', p.years = 3
RETURN p.name AS name, p.title AS title, p.years AS years;
    예상 결과

    한지우 · 선임 · 3

    12-2 · 있으면 올리고 없으면 만들기
    MATCH (p:Person {name: '한지우'})
MERGE (s:Skill {name: 'Cypher'})
MERGE (p)-[h:HAS_SKILL]->(s)
  ON CREATE SET h.level = 1
  ON MATCH  SET h.level = h.level + 1
RETURN p.name AS name, s.name AS skill, h.level AS level;
    예상 결과

    처음 실행하면 level 1(관계 생성), 한 번 더 실행하면 level 2(기존 관계 갱신). 두 번 실행해서 차이를 확인하세요.

    12-3 · 임시 직원 추가
    MATCH (t:Team {id: 'T1'})
CREATE (p:Person {id: 'P99', name: '임시사원', title: '사원', years: 0})-[:WORKS_IN]->(t)
RETURN p, t;
    12-4 · 그냥 지우기 (오류가 나는 것이 정상)
    MATCH (p:Person {id: 'P99'})
DELETE p;
    예상 결과

    G1001: Dependent object error - edges still exist 오류. Neo4j는 관계가 남아 있는 노드를 지우지 못하게 막습니다.

    12-5 · 관계까지 함께 지우기
    MATCH (p:Person {id: 'P99'})
DETACH DELETE p;
    예상 결과
